# Comprehensive Refactoring Plan: Research Workspace

- **Date:** 2026-10-10
- **Task ID:** `2026.10.10-refactoring-plan`
- **Target Repository:** `https://github.com/vernikr/research-workspace`
- **Author:** Senior Staff Software Engineer / Systems Architect
- **Status:** Proposed & Ready for Execution

---

## 1. Executive Summary & Architectural Overview

The `research-workspace` repository provides an agent-driven deep-research environment orchestrating the **HyperResearch** pipeline, coupled with a remote browser automation lane hosted on dedicated infrastructure (`38.244.152.2`).

The system was developed under rapid iteration, prioritizing working prototypes, diagnostic scripts, and edge-case mitigations for the Freebuff Desktop/CLI harnesses. While functionally robust, this rapid growth resulted in noticeable architectural technical debt:

1. **Severe context consumption and token waste:** Documentation is highly repetitive across multiple root files and guides; code patterns (study path resolution, frontmatter parsing, hash generation, tempfile creation) are duplicated across 21 individual bash scripts.
2. **Hardcoded user and environment paths:** Hundreds of references to `/Users/vernikr/...` in `CLAUDE.md`, `.claude/skills/`, and documentation break cross-environment portability and confuse AI agents working in clean or cloud environments.
3. **Fragile edge cases and hidden bugs:** Critical defects exist in key validation scripts (e.g., `bin/report-check.sh` fails with false positives when verifying non-active studies; `bin/browser-fetch.sh` leaks temp files and lacks Linux hashing fallbacks; `doctor.sh` omits checks for the server's primary AmneziaWG VPN).
4. **Complete absence of CI/CD:** No automated linting, type-checking, or unit/integration testing exists. Changes must be validated manually, slowing down development cycles.
5. **Inefficient execution and process overhead:** Frequent bash subshell forks (`sed`, `date`, `wc`, `jq`) inside high-frequency logging loops cause noticeable execution slowdowns during batch operations.

This refactoring plan provides an actionable, balanced, and pragmatic roadmap to resolve these issues. It enforces strict prioritization based on developer agent acceleration, reliability, performance, and user agent experience, while strictly avoiding over-engineering and unwarranted abstractions.

---

## 2. Priority Hierarchy & Core Engineering Trade-offs

The plan strictly adheres to the requested priority hierarchy:

```
text[Priority 1: Developer Agent Optimization]
  ├── Volume: Eliminate duplicate logic, dead code, redundant checks, outdated docs
  ├── Structure: Modularity, consistency, shared libraries, navigation
  └── CI/CD: Automated fast checks, linting, regression testing (<45s execution)
        ↓
[Priority 2: Reliability & Bug Elimination]
  ├── Resolve cross-study validation bugs in report-check
  ├── Fix shell portability, tempfile leaks, and parsing inconsistencies
  └── Fix environment assumptions & align with production server specs
        ↓
[Priority 3: E2E Performance & Resource Discipline]
  ├── Eliminate bash fork storms in logging/status checks
  ├── Parallelize network diagnostics
  └── Optimize memory footprints for bridges and fetchers
        ↓
[Priority 4: User Agent Experience (AX/DX)]
  ├── Provide unified CLI entrypoint (bin/rw) with self-healing symlinks
  ├── Streamline setup to be idempotent, quiet, and fast
  └── Provide clear diagnostic output with actionable remediation hints
```

### Engineering Guardrails:

- **No speculative abstractions:** Do not introduce heavy compiled languages, microservices, or complex build systems for tasks that standard POSIX/Bash and Python 3 handle cleanly.
- **Strict backward compatibility:** Existing script interfaces (`bin/study.sh`, `bin/tunnel.sh`, `bin/doctor.sh`, etc.) must remain functional as thin shims over modular core logic.
- **Context-first documentation:** Evergreen files (`AGENTS.md`, `CLAUDE.md`, `README.md`) must be kept compact, token-dense, and free from volatile machine details or historical narratives.

### 3.2. Hidden Bugs & Edge Cases

1. **Critical: `bin/report-check.sh` Hardcoded Active Symlink Resolution (Line 58)**
  - *Bug:* Inside the Python check block, the script executes `notes_dir = root / "research" / "notes"`.
  - *Impact:* It resolves the active symlink at repository root rather than the target study's notes directory (`studies/<target>/research/notes`). When checking any report other than the currently active study (or when symlinks are unlinked), **100% of wikilinks are flagged as nonexistent FAILs**, and quote integrity compares against the wrong study's notes.
2. **Missing Study Tag Parameter Resolution in `bin/report-check.sh`**
  - *Bug:* Calling `bash bin/report-check.sh <vault_tag>` only checks `$NOTES_DIR/final_report_${TARGET}.md` in the *active* study rather than searching `studies/${TARGET}/`.
3. **Tempfile Descriptor Leak in `bin/browser-fetch.sh` (Line 71)**
  - *Bug:* `RAW="$(curl ... 2>/tmp/browser-fetch-curl.$$ || true)"`. The file `/tmp/browser-fetch-curl.$$` is read in log calls but never removed.
  - *Impact:* Thousands of orphaned temp files accumulate on active research nodes over long runs.
4. **Shell Portability Failure in `bin/browser-fetch.sh` (Line 49)**
  - *Bug:* `HASH="$(printf '%s' "$URL" | shasum -a 256 | cut -c1-8)"`. Unlike `study.sh`, it lacks a fallback to `sha256sum`.
  - *Impact:* Fails on standard Linux systems where Perl's `shasum` is not pre-installed.
5. **Syntax Bug in `bin/log-report.sh` (Line 73)**
  - *Bug:* `jq -r '\(.component) \(.event)' "$TMP" 2>/dev/null` fails with a syntax error because string interpolation requires surrounding quotes (`"\(.component) \(.event)"`). The line always fails and silently triggers the fallback.
6. **Unquoted Expansion in `bin/log-report.sh` (Line 46)**
  - *Bug:* `cat $FILES | jq ...` relies on word splitting; directories with spaces break execution.
7. **Inconsistent Note List Schema Handling**
  - *Bug:* `mission-status.sh` only parses `.data` and `.notes` arrays; `doctor.sh` parses bare arrays, `.data`, `.data.notes`, and `.notes`. CLI version changes cause status reporting to break unpredictably.
8. **Fragile Datetime Parsing in `bin/mission-status.sh`**
  - *Bug:* Uses `datetime.datetime.strptime(sys.argv[1].replace("Z",""), "%Y-%m-%dT%H:%M:%S")` and deprecated `datetime.datetime.utcnow()`. Fails on ISO timestamps containing timezone offsets (`+00:00`) or fractional seconds.
9. **Symlink Collision / Destruction Hazard in `bin/merge-runs.sh`**
  - *Bug:* Writes directly to `$ROOT/research/notes` and `$ROOT/research/runs/$TAG`. If root symlinks are unlinked, it creates physical directories at the root, permanently preventing `bin/study.sh` from linking active studies without manual repair.
10. **VPN Status Mismatch in `bin/doctor.sh`**
  - *Bug:* `doctor.sh` inspects only `x-ui` (the backup VPN). Per `server-spec.md`, the primary VPN is `awg-quick@awg0.service` (AmneziaWG). If `x-ui` is stopped for maintenance while AmneziaWG is healthy, `doctor.sh` returns a false `[FAIL] server-vpn`.
11. **Arbitrary Variable Expansion Hazard in `bin/mcp-bridge-check.sh`**
  - *Bug:* `eval "val=\${$var-}"` processes unsanitized strings from `mcp.json`.
12. **Fresh Clone Disconnection**
  - *Bug:* On a clean `git clone`, `studies/.active` and root symlinks do not exist. Any tool invoked without first running `study.sh ensure` fails with cryptic missing file errors.

### 3.3. E2E Performance & Resource Inefficiencies

1. **Bash Subshell Thrashing in `bin/log.sh`:**
  - Every single call to `log_info`/`log_debug` executes multiple subshells: `date -u`, `sed` inside `log_redact`, `sed` inside `_log_json_escape`, `wc -c` inside `_log_rotate`, and `tr`.
  - In tight loops (e.g. processing 100 notes or links), this spawns hundreds of fork/exec processes, causing observable CPU spikes and latency on macOS and single-core Linux servers.
2. **Serial Network Probes in `bin/doctor.sh`:**
  - Checks for GitHub API, Firecrawl quota, Apify quota, remote SSH status, and local tunnel HTTP status run purely sequentially with 10–15s timeouts each. A single slow endpoint delays the health check by 20–30 seconds.
3. **Redundant Disk I/O:**
  - `study.sh list` executes `du -sh` on every study folder serially. In workspaces with dozens of past studies, listing studies takes several seconds.

### 3.4. AI Agent Experience & Usability (AX/DX)

1. **Tool Discovery Friction:** 21 executable scripts in `bin/` with disparate naming conventions (`doctor.sh`, `study.sh`, `report-check.sh`, `desktop-diag.sh`, `skills-install-user.sh`). AI agents frequently guess command names or search through `bin/` multiple times per task.
2. **Setup Friction:** Setup displays an overwhelming 100-line wall of terminal instructions that exceeds the context needed for a simple automated installation.
3. **Error Remediation Gaps:** When tools fail (e.g. tunnel inactive, symlink missing), error messages are verbose but lack a clear, single-line copy-paste recovery command.

## 4. Architectural Target State

### 4.1. Core Library Modularization (`bin/lib/`)

Extract shared operations into clean, sourced bash libraries under `bin/lib/`:

- **`bin/lib/core.sh`**:
  - `rw_root()`: Reliable repository root detection.
  - `rw_study_path(tag)`: Canonical study directory resolver (active or by tag).
  - `rw_ensure_links()`: Safe, self-healing symlink repair.
  - `rw_hash8(str)`: Portable 8-char SHA-256 (handles `sha256sum`, `shasum`, and pure Python fallback).
  - `rw_read_frontmatter(file, key)`: Robust YAML frontmatter parser.
  - `rw_tempfile(prefix)`: Safe temporary file allocation with automatic exit traps.
- **`bin/lib/logging.sh`**:
  - High-performance structured logging. Replaces multiple `sed` forks with built-in bash parameter expansion `${var//search/replace}`.
  - Automatic JSON serialization without subshells.
- **`bin/lib/doctor.sh`**:
  - Backgrounded, parallel health check engine executing remote SSH, HTTP API, and provider quota checks concurrently via background jobs (`&` and `wait`).

### 4.2. Unified CLI Front-End (`bin/rw`)

Introduce a single, intuitive multi-call dispatcher `bin/rw`:

```
Bashbin/rw <command> [options]

Commands:
  study      Manage research studies (new, list, use, current, ensure, status, remove)
  doctor     Run environment and infrastructure diagnostics (--json, --no-remote, --fast)
  check      Validate report structure, wikilinks, and verbatim quotes (--json)
  tunnel     Manage SSH tunnel to remote browser lane (start, stop, check, ensure, vnc)
  status     Inspect active mission and pipeline progress
  report     Generate post-run summary report (--write)
  fetch      Fetch blockable URL via server browser lane
  setup      One-command environment and pipeline installation
```

*Backward Compatibility Guarantee:* Existing scripts (`bin/study.sh`, `bin/tunnel.sh`, `bin/doctor.sh`, etc.) remain executable and forward their arguments directly to `bin/rw <cmd>`, guaranteeing that zero existing prompt workflows, skills, or user aliases break.

### 4.3. Documentation Consolidation & Token Diet

Refactor documentation according to the "Single Source of Truth" pattern:

- **`AGENTS.md` (Contract & Hard Rules):** Trim from 18 KB to ~8 KB. Retain only invariant rules: turn contracts, symlink discipline, browser lane security boundaries, model policies, and logging rules. Remove duplicated tutorials.
- **`CLAUDE.md` (Agent Router & Tool Reference):** Purge all `/Users/vernikr/...` paths. Use `bin/hpr.sh` and relative paths. Retain only pipeline mechanics, query gospels, and CLI command references.
- **`README.md` (Workspace Overview & Quickstart):** Keep clean, readable, and concise. Focus on human and agent onboarding.
- **`docs/` Indexing:** Introduce `docs/README.md` as a directory index. Compact `docs/desktop.md` by archiving historical 2026-10-05 debug transcripts into `docs/archive/`, reducing file size by 65%.

### 4.4. Automated CI/CD Quality Gate (`.github/workflows/ci.yml`)

Implement a lightning-fast GitHub Actions workflow running in <40 seconds:

1. **Static Analysis:**
  - `shellcheck` across all `bin/*.sh` and `bin/lib/*.sh`.
  - `node --check` / linting on JavaScript files.
  - Syntax validation of all JSON templates (`mcp.json.example`).
2. **Automated Unit & Integration Tests (`tests/`):**
  - Study lifecycle test (`study.sh new` -> `use` -> `list` -> `ensure` -> `remove`).
  - Report verification test (`report-check.sh` on synthetic valid/invalid reports and cross-study targets).
  - Logging redaction test (verifying that PATs, keys, and authorization headers are never written to logs).
  - Mock tunnel and doctor offline execution test.

# Freebuff Desktop — Adapted Runbook

> **Studies layout:** Each research mission is a self-contained `studies/<tag>/` directory; repo-root paths (`research/`, `mission/`, `sources/`, `.hyperresearch/`) are symlinks to the active study. Use `bash bin/study.sh` or `bash bin/rw study` to manage them.

How to run this workspace in the Freebuff **Desktop** app instead of the CLI. Desktop isolates parallel agents in separate workspaces, with an internal prompt queue and reusable workflows.

---

## 1. Core Architecture & Verification Gates

Desktop reads project root instructions (`AGENTS.md`) and `.claude/skills/`.

Four gates must be satisfied for full Desktop integration:

1. **Instructions loaded:** Desktop reads `AGENTS.md` at project root.
2. **MCP server configured:** Use `bash bin/mcp-install.sh --user` to configure `browser-agent` in `~/.agents/mcp.json` (avoids repo-scope untrusted skips). Ensure `browser-agent` is toggled **ON** in Desktop Settings → MCP.
3. **Skills installed:** Pipeline skills reside in `.claude/skills/` (and optionally `~/.agents/skills/` via `bash bin/skills-install-user.sh`).
4. **Browser lane enforcement:** Local Chrome/Playwright/Peekaboo are strictly forbidden for research. All external fetches route through the remote server (`bin/browser-fetch.sh` or MCP `browser_fetch`).

## 6. Limits, Safety & Troubleshooting

- **One writer per checkout:** Do not run concurrent threads on the same git checkout. Use Topology B (worktrees) for parallelism.
- **Single browser tab:** Remote server maintains 1 Chrome tab under mutex lock. Only the browser-owner thread may fetch.
- **Silent model downgrades:** If output quality drops, verify the model in the Desktop thread picker.

| Symptom | Cause | Solution |
| --- | --- | --- |
| Thread ignores instructions | Project instructions not picked up | Open exact workspace folder; re-run wiring prompt |
| Pipeline skills not found in thread | Desktop has not reloaded skills | Run `bash bin/skills-install-user.sh`, restart Desktop |
| `doctor` OK but no `browser-agent` tools | Server toggled off in app settings | Settings → MCP → toggle `browser-agent` ON → restart app |
| Node command failed in MCP | Ephemeral node shim in terminal | Run `bash bin/mcp-install.sh --user` to pin absolute stable Node path |
| API status 000 | Tunnel dropped during sleep | Run `bash bin/tunnel.sh ensure` or install watchdog |
| Rate limits (429/403) | Provider throttle | Check `bash bin/log-report.sh`; apply fallback ladder in `docs/limits.md` |

## What the first real wiring run established (Desktop, 2026-10-05)

- **`AGENTS.md` is loaded** from the project root: the thread quoted its first lines and the `doctor` findings verbatim.
- **Home-level servers connect, the project file does not.** In both wiring runs the thread listed every **home-level**
  `~/.agents/mcp.json` server (chrome-devtools, chrome-devtools-live, playwright, peekaboo, figma\*, firecrawl, exa,
  apify, serena, tinyfish, keenable…) and never `browser-agent` from `<repo>/.agents/mcp.json`, even with the file in
  place. Two mechanisms explain that, and the fix covers both:
  1. **the trust gate** — any repo-scoped `.agents` dir holding `mcp.json` is untrusted until the user says otherwise;
    the Desktop runtime, being non-interactive, **skips it silently** (it prints only a note in its own log, never in
    the chat). Trust is recorded per absolute path in `<configDir>/trusted-agent-dirs.json` (`~/.config/manicode` by
    default, or `$FREEBUFF_CONFIG_DIR`), and can also be granted with `--trust-agents` / `CODEBUFF_TRUST_AGENT_DIRS=1`;
  2. **`process.cwd()`** — the loader resolves the project scope relative to the process working directory, so a
    Desktop process started somewhere else will not find `{cwd}/.agents` at all.
    Because `~/.agents` is always trusted and always loaded, **the user scope is the supported Desktop route**:
    `bash bin/mcp-install.sh --user`. The project scope stays useful for the CLI (one interactive `freebuff` run in the
    repo, answer `y`, and it is trusted from then on).
- **Resolution (2026-10-05, thread `0cd0c3eb`): four gates, in this order.**
  1. the entry exists and the bridge really starts where the app lives — `bash bin/mcp-bridge-check.sh`,
    `[OK] mcp-node-stability` in `doctor` (a per-shell fnm node path dies with the terminal that created it);
  2. the app has been restarted since the config changed — the server list is built at app boot;
  3. the project scope is untrusted, so the home scope is what Desktop actually sees — `bin/mcp-install.sh --user`;
  4. **the server is enabled in the app's MCP settings** — the last one, and the one no file check can see.
    Only after all four did the wiring thread report the four tools (`browser_status`, `browser_fetch`,
    `browser_action`, `browser_agent`) and `[OK] browser-agent-api: status 200`.
- **MCP config is read at boot**: after any change to a config file, **open a NEW thread** (reopening the project is not
  always enough; restarting the app is the sure version). A file written mid-session is not picked up (CLI issue #957).
- **A missing tool can also be a bridge that fails to start — or a node path that only exists in your terminal.**
  Under a version manager, `command -v node` inside a shell often points into a per-shell shim directory
  (`~/.local/state/fnm_multishells/<pid>_<ts>/bin/node` for fnm, similar for volta) that stops existing when that
  terminal closes; a Finder-launched app cannot execute it, so the server never starts while `doctor` in the shell
  says everything is fine. `bin/mcp-install.sh` now resolves the **stable** install tree
  (`~/.local/share/fnm/node-versions/*/installation/bin/node`, `~/.nvm/...`, Homebrew, system) and warns if only an
  ephemeral one is available; `doctor` reports `[WARN] mcp-node-stability` in that case, and `MCP_NODE=/abs/path`
  overrides. Re-run `bash bin/mcp-install.sh --user` after such a warning — it rewrites the entry in place.
- **A missing tool can also be a bridge that fails to start.** `bash bin/mcp-bridge-check.sh` reads the configured
  `command`/`args`/`env`, pipes a real MCP handshake into it and counts the tools it answers with — it separates
  "the config was not read" from "the server died at startup" (stale bridge path after a repo move, or `node` missing
  from a Finder-launched app's PATH). `bin/mcp-install.sh` now pins the **absolute** node path, and `doctor` runs this
  check (`[OK] mcp-bridge`).
- **This build does not offer a skills list to the thread.** With the skills on disk the pipeline still works, but the
  thread must be told to read `.claude/skills/hyperresearch/SKILL.md` (entry) and the numbered step skills; a missing
  directory means setup never finished — that is what `[WARN] skill-installed` reports.
- **`hyperresearch install` takes no `--target`** (0.12.0): the correct call is `hyperresearch install . --profile full --json`, and it writes `.claude/skills/`. `bin/setup.sh` does exactly that and warns instead of dying if it fails.
- **`freebuff --version` is a trap**: the CLI is a launcher and that call can download and start the app
  ("Download complete! Starting Freebuff..."). `bin/doctor.sh` no longer calls it.
- **Home-level browser/desktop servers are connected by default.** Until you disable them, the protection is the rule in
  `AGENTS.md` §4 plus the `local-browser-mcp` check in `doctor`. If you never use `peekaboo` (macOS screen control) or
  `chrome-devtools*`, remove them from `~/.agents/mcp.json` for research sessions.

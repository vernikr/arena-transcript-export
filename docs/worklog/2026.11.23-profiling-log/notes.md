# Profiling log (default on, toggleable)

- Added `extension/content/profile.js` — a bounded, zero-I/O profiler for one export run: no timers, no DOM reads, no I/O during the run (only `performance.now()` and small object pushes); the finished log is built once at the end and hard-capped (64 KiB) so it stays compact and agent-parseable even for very large source pages.
- The profile document records: header (source URL, chat UUID, tool version, options, outcome), per-run totals (messages, windows, spoilers expanded/stuck/total, left-collapsed, history pages/stability/message counts, Markdown chars/bytes), per-phase timings (`history`, `expand`, `cleanup`, `process`) with max/count, per-message timing aggregates (count, mean, p95, max, slowest message index; samples capped, honest about the cap), the slowest windows (capped at 64, evicted/counted beyond that), best-effort Chromium heap samples (`performance.memory`, absent in jsdom), and a short milestone event list (export start/done, history done, process done, serialize assembled).
- `main.js` wires it through `processMessagesInWindows` (per-window `expandMs`/`serializeMs`/`cleanupMs`/`ms`/bytes/spoilers, per-message timing, `stuckSpoilers` and `windowCount` in the return value) and `runExport` (phases timed, milestone events, `AREX._job.profile` retained until ACK, attached to both the success and the failure `AREX_RESULT_END` so cancelled/errored runs keep their log). Disabled via `options.profile: false` (default on) — profiling then is a no-op and the hot path never pays for it.
- `result-store.js` gains `latest-profile` persistence (`saveProfile`/`loadProfile`/`clearProfile`), included in `clear()`; background persists it next to the snapshot on success (validated, bounded) and on failure (best effort); the popup shows a compact summary (total time, phases, slowest window, p95/max message) and a **Download profile (JSON)** button, and hides it when profiling is off or the artifact is unavailable.
- New popup option **Performance profiling** (checked by default, remembered in `chrome.storage.sync`, passed through `AREX_EXPORT_START`).
- Tests: new `test/profile.test.mjs` covers disabled/no-op mode, the document shape, window/event bounding and keep-slowest semantics, the hard byte budget, and integration through `processMessagesInWindows`; `test/popup-ui.test.mjs` now checks the profile card and the JSON download; `test/harness.mjs` and `test/main-port-reconnect.test.mjs` load `profile.js`. Full suite green.
- Not covered: the Node benchmark scripts are unchanged (profiling is browser-pipeline scoped by design); per-node/per-message raw events are intentionally not recorded — the log stays aggregate-only.

# Background coordinator (Stage 1 of performance-and-background-plan)

- Implemented `docs/performance-and-background-plan.md`, Stage 1: popup-independent export lifecycle.
- New `extension/shared/result-store.js` (moved from `extension/popup/result-store.js`): works in both the popup (`window.indexedDB`) and the service worker (`self.indexedDB`), and keeps a tiny `latest-meta` record (filename, stats, bytes, tabId, chatUuid, sourceUrl, createdAt) so the UI can query snapshot metadata without reading a multi-megabyte markdown string. One-time upgrade derives metadata from existing snapshots.
- `extension/background.js` is now the central coordinator on top of the theme-icon bridge:
  - `jobsByTab` registry (`running`/`done`/`error`), mirrored to `chrome.storage.session` (progress capped, markdown never persisted there) so an MV3 service-worker restart does not lose state; stale `running` jobs older than 45 s without a heartbeat are marked as lost.
  - `AREX_JOB` port from the content script: receives `AREX_JOB_START` (incl. re-sync after SW restart), progress events, heartbeats, and the result as ≤ 2 MB `AREX_RESULT_CHUNK`s + `AREX_RESULT_END`; the background writes the snapshot to IndexedDB itself, then posts `AREX_RESULT_ACK` so the Arena tab can release its in-memory copy. If the IndexedDB write fails, the assembled result is kept in memory and surfaced via `AREX_GET_INMEMORY_RESULT` so an open popup can still recover it.
  - `AREX_POPUP` port from the popup: instant `AREX_STATUS`, live progress relay, `AREX_EXPORT_START` proxy (the `chrome.scripting.executeScript` injection moved here from `popup.js`), `AREX_EXPORT_CANCEL` forwarding, `AREX_JOBS` listing for the "export running in another tab" banner.
  - `chrome.tabs.onRemoved` / `onUpdated` mark a `running` job as failed instead of leaving it spinning forever.
- `extension/content/main.js`: opens the `AREX_JOB` port for the whole export, heartbeats every 20 s, streams the markdown in 2 MB chunks, releases the result only on `AREX_RESULT_ACK`, and supports cancellation via `AREX_EXPORT_CANCEL` (`AbortController`; `AREX.waitFor` is abort-aware; opened spoilers are collapsed in `finally`). The export no longer awaits the popup for persistence.
- `extension/popup/popup.js` + `popup.html`: UI is driven by the background port instead of a direct tab connection; added a determinate `#progressBar` and a `Cancel export` button shown while running; the popup restores live progress at any stage after reopening (including `done`, loading the snapshot from IndexedDB), and shows a switcher banner when an export is running in another Arena tab.
- Tests: rewrote `test/main-port-reconnect.test.mjs` for the job-port architecture, updated `test/popup-ui.test.mjs` to simulate the background coordinator, added `test/background-coordinator.test.mjs` (progress relay, chunked result reassembly + IndexedDB persistence, ACK, cancel forwarding, error paths, tab-close handling, script injection). Full suite green.
- Manifest unchanged: `scripting` and `storage` already cover the new flow; `chrome.storage.session` ships with `storage`.
